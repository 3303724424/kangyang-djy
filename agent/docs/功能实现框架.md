# 都江堰银龄康养旅居功能实现框架

## 模块划分

| 模块 | 责任 | 当前实现 |
| --- | --- | --- |
| `domain` | 定义长者、景点、酒店、陪伴员、行程等数据结构 | `models.py` 数据类。|
| `data` | 加载并校验本地 JSON 数据 | `repository.py`。|
| `algorithms` | 完成评分、行程排程、人员匹配、人工确认提示 | 纯 Python、本地可运行。|
| `services` | 组合各算法，输出一个完整安心旅居方案 | `care_plan_service.py`。|
| `tests` | 校验结果中有午休、人工确认项、匹配服务人员 | Python `unittest`。|

## 本地算法路线

```text
结构化需求
  -> 景点适老评分
  -> 每日选取 1 个核心主题 + 1 个低强度活动
  -> 加入午餐午休与交通缓冲
  -> 酒店产品加权筛选
  -> 学生陪伴员规则评分与排序
  -> 生成需人工确认项
```

### 适老景点评分

```text
总分 = 偏好匹配 * 40
     + 行动需求适配 * 25
     + 休息设施 * 15
     + 预算适配 * 10
     + 距离连续性 * 10
```

评分使用可解释字段，便于运营人员修改权重和复核结果。后续有足够真实订单与评价数据后，再引入协同过滤或学习排序。

### 行程排程

1. 按得分选取景点；
2. 使用 Haversine 距离排序，避免明显跨区往返；
3. 每日安排上午核心游览、午餐/午休、下午低强度活动；
4. 连续活动不超过 3 小时；
5. 输出开放状态、天气、库存、身体情况等人工确认项。

### 学生陪伴员匹配

先按“已完成培训、可服务日期、行动协助能力”过滤，再综合文化讲解、康养陪伴、无障碍协助等标签评分。订单量增多后可将该模块替换为最大权重二分图匹配。

## 推荐开发顺序

1. 补充真实但经过审核的都江堰 POI、酒店和康养活动数据；
2. 完善需求表单与本地规划引擎；
3. 完成学生陪伴员审核、排班与服务记录；
4. 加入酒店合作产品、意向预约与运营后台；
5. 最后再加入前端页面、数据库持久化和内部服务接口。
